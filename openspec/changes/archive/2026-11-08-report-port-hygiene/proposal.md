# Proposal: report-port-hygiene

## 背景

`serve` 不显式给 `--port` 时从 13680–13699 **全池随机**；该池包含本部署的正式端口
13689。macOS/Bun 在主机名解析差异下允许同一端口以不同地址族/复用方式并存，于是开发/测试
实例会短暂"偷走" 13689 的连接：

- 实证 2026-11-08：`watch`（manager 订阅）在 13689 上收到 `/healthz.dataDir=/var/folders/.../report-test-UHVojh/data`，
  即一个测试实例；正式库未受影响（posts=64 / max_seq=389 / 未读 0），但订阅吃错后端会静默吞/丢消息。
- QA 侧已用 `scripts/qa/qa-serve.mjs` 排除保留端口，但产品自身的随机池没有约束。

## 变更内容

1. 随机端口池排除正式端口 **13689**（生产实例始终显式 `--port 13689`；随机池只服务开发/测试实例）。
2. 补单测：`shuffledPorts()` 在大量采样下永不返回 13689，且仍覆盖 13680–13699 的其它端口。
3. 订阅侧（report-channel 插件）已加实例身份守卫（dataDir 不匹配即拒绝消费）——本 change 只做源头治理。

## 非目标

- 不改端口段（仍 13680–13699）；不引入新的保留端口清单；不动其它会话的 13690/13696/13697。
- 不改 `--port` 显式指定路径（含 CONFLICT 报错语义）。
