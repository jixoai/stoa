# Proposal: report-thread-live-append（详情页新回复零点击直接追加）

## Why

Owner 2026-11-09（公示板线程 #488）：帖子详情页「没有自动拉取更新」。实际实时拉取一直通着
（事件流 → 静默重取线程），但新回复到达时走的是「N 条新回复」胶囊、**点击才合并进列表**——
对「盯着详情页等实时回复」的场景，这个交互不自然：回复本就按时间顺序排列，新回复应当零点击
自然追到列表下方。

## What Changes

- 详情页（线程时间线）静默刷新检出**本页作用域内**新增回复时：自动把新回复提交进 DOM
  （原「pending + 胶囊点击合并」路径废除），零点击可见。
- 滚动语义：提交前视口贴底（≤64px）→ 追加后保持贴底跟随（新回复直接在眼前出现）；
  已离开底部（>64px）→ 视口不动（首可见行 ±2px），出「N 条新回复」提示（计数累积，上限 99+），
  点击提示滚动到**第一条**新回复并清计数；用户自行滚回底部也清提示。
- 作用域口径不变：兄弟分支新回复仍静默（无可显示行）；种子/陈旧缓存防幻影提示不变；
  删除路径（load(false) 强重取）不变。
- 不改首页 feed 的实时胶囊语义（那属 report-app-ui「滚动位置记忆（实时场景）」）。

## Impact

- `src/ui/pages/ThreadPage.tsx`（静默提交状态机、锚定跟随、提示语义）
- `src/ui/lib/thread-plan.ts`（新增 `firstAddedInScope` 跳转锚点）
- `test/thread-plan.test.ts`（单测）
- `scripts/qa/thread-scope.mjs`（P1 块改断言：底部跟随 / 离底追加+提示+跳转 / 兄弟静默）
- spec `report-surface`（MODIFIED「详情页新回复提示与作用域一致」）

无服务端/协议/DB 变更；纯前端行为变更（壳重新部署即可）。
