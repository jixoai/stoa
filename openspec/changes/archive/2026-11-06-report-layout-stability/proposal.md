# Proposal: report-layout-stability

## 背景

Owner 2026-11-06 走查发现两个体验缺陷（均为「已上线」状态下的真实问题）：

1. **首次进入底部导航缺失**：直接打开壳（`?ep=` 冷启动 / 深链直达子页）时，底部四导航
   不出现，刷新一次才出现。
2. **路由导航完成后布局抖动**：从时间线进入帖子/成员/标签页，转场结束、数据返回后整页
   重新排版（骨架被真实内容替换时高度跳变），View Transition 也因为目标页当时还没有内容
   而失去可变形元素，转场观感退化。

根因（实证）：

- 底部导航用 `position: fixed` 贴底。它在任何祖先产生 transform/containing block
  （转场快照、motion 兜底、宿主 WebView 的合成层）或移动端可视视口与布局视口不一致时
  都会脱离预期位置；这是「刷新后才有」这类不可复现问题的典型形态。
- 目标页数据在**转场回调之后**才开始请求：`startViewTransition` 的 commit 里渲染的是
  空壳 + 居中 spinner，网络回来后才长出内容 → 转场快照两张都是「空页」，随后内容插入，
  产生一次性 CLS 与滚动/焦点漂移。

## 变更内容

1. **壳布局**：底部导航改为壳的 **flex 子元素**（`shrink-0`、固定 56px + safe-area），
   与主列同属一个布局流；`main` 与详情覆盖层删除为 fixed 导航预留的 `padding-bottom`。
   导航不再依赖任何定位上下文，首帧与壳同帧出现。
2. **转场时序（Owner 指定）**：目标页在 View Transition 的 commit 回调里**先用已见数据
   完成排版**（帖子/线程/成员/标签都有客户端实体缓存，缓存未命中则用与真实卡片同度量的
   骨架）；数据请求在转场期间发出；转场结束后骨架→内容做交叉淡入，容器高度从骨架高度
   平滑过渡到内容高度。
3. **实体缓存与意图预取**：新增 `state/cache.ts`（帖子 600 条上限、线程整包、成员资料、
   时间线快照；按 id 去重、内存态、不持久化）。`PostCard`/成员行在 pointerenter/down 时
   预取线程/资料；时间线用 `cacheKey` 写回最后一批，返回同一路由时首帧直接有内容。
4. **线程页首帧**：只有单帖缓存时合成「只有焦点帖」的线程（真实卡片 + 回复区骨架），
   完整线程返回后在焦点帖**下方**补全；「N 条上文」出现时用 layout effect 同帧重新贴顶。
5. **可验证门禁**：新增浏览器脚本 `src/ui/.qa/stable.mjs`（帧级采样）断言：
   壳与导航同帧出现、导航全程存在且位置不变、转场结束后焦点帖/顶栏/导航/滚动高度稳定、
   **导航窗口内 CLS = 0**、tab 切换不新增历史、深链直达导航在首帧；移动/桌面两档。

## 非目标

- 不改任何后端 API、数据结构与认证语义。
- 不做跨会话持久化缓存（刷新仍重新取数；滚动记忆沿用既有实现）。
- 不解决「媒体加载引起的高度变化」这一独立问题（`MediaRef` 无宽高元数据，需要上传侧
  记录尺寸后按比例预留）；本 change 只保证**导航窗口**内零位移，实测首屏媒体 CLS 0.058
  仍记入 `tasks.md` 的后续项。
