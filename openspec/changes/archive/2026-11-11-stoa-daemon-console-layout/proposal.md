# Proposal: stoa-daemon-console-layout（挂载入口 Sheet 化 + 控制台布局重做）

## Why

Owner 2026-11-10：「添加理论上不应该直接展示出来的，添加理论上应该用 sheet 或者 dialog 来提供。」

Owner 2026-11-11：用 OpenDesign 优化页面设计——X + shadcn + solid-glass 的 UI/UX 基础不动，
主要改进产品体验，并在组件库风格标准上给出更好的布局。

视觉评审（六张真实截图，390/1280）确认的现状问题：

1. 首屏被常驻挂载表单占满：390 下服务列表从 y≈620 才开始；挂载成功截图里第二张服务卡被视口切断。
2. 操作权重倒挂：「口令 / 打开 / 停止」三个同尺寸描边按钮，「停止」是行内唯一红色，视觉焦点压过「打开」。
3. 390 触控目标偏小：分段胶囊约 28px、行内按钮约 30px、口令框内图标可点区约 20px。
4. 表单错误文案距出错字段约 260px（390），靠近折叠边缘。
5. 1280 内容列仅约 800px，两侧各约 230px 空白，像文档页而不是控制台；服务行没有列锚点。
6. 空态两条路径并列（表单 vs CLI），CLI 行在 390 被视口底边截断。
7. 状态与位置同为并排小徽标，真正该被一眼看到的「运行中」被稀释；stopped 行整体降透明。

## What Changes

- **挂载入口 Sheet 化**：常驻表单 Card 移除；header 主按钮 + 空态 CTA 打开官方 `Sheet`。
  桌面右侧（约 420–480px）、移动底部抽屉（`max-h: 85dvh`，内部滚动）。
  提交成功 → Sheet 关闭 + toast + 表单重置；取消/关闭 → 清错误并重置；焦点回触发钮。
- **服务列表成为首屏主角**：状态概览（运行中 N / 共 M）、服务行按
  「身份+状态 → 入口 → 元信息 → 操作」分层；「打开」为唯一主操作，口令为次级，
  停止/移除降级（菜单或二次确认）；stopped 行去饱和而非整体降透明，且不提供失效的「打开」。
- **空态**：单一主路径「挂载第一个服务」（打开同一 Sheet）+ 折叠的 CLI 备选，不再并列。
- **响应式**：390 首屏（844 高）可见概览 + ≥1 服务行 + 明确添加入口，无横向溢出；
  1280 内容区放宽并让服务行信息按列对齐（宽度与档位见 design.md）。
- **次级信息可操作**：状态目录与行内路径可复制；截断文本有 title 兜底。
- **表单细节**：错误就地落在字段下方；端口校验失败即时清除；可选字段不再逐个标注「可选」。
- **契约**：沿用 `daemon-mount-*` / `daemon-location-*` / `daemon-pick-dir` testid；
  新增 `daemon-mount-open`、`daemon-mount-sheet`。组件只用官方收编件，视觉令牌不变。

## Impact

- 纯 UI/布局变更：后端 API、数据模型、动作语义零改动。
- 390/1280 的首屏信息密度与操作动线改变；QA 脚本需增加「打开 Sheet」步骤与新截图。
- 版本建议 v0.3.1（patch）；npm 发布走既有 CI/OIDC。

## Out of Scope

- 后端字段/动作新增（搜索、筛选、分组仅允许基于既有字段；本期不做）。
- 多用户口令/账号体系；daemon 远程访问与鉴权。
- 1280 的 master–detail 双栏（OpenDesign 备选方向，本期只做列表 + 行内展开的监控优先布局；
  若设计稿明确要求双栏，按 design.md 记录再评估）。
