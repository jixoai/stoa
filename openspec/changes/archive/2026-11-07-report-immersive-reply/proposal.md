# Proposal: report-immersive-reply

## 背景

Owner 2026-11-07 走查：线程页的回复框**常驻展开**，噪声大、也抢走了阅读焦点。X 的做法是
先收起、由明确意图展开；一旦展开就是**沉浸式编辑环境**（移动端全屏，桌面 Dialog）：

- 移动端：顶部 X（关闭）在左、`回复` 提交在右；上方是原帖上下文；`回复给 @xxx`；正文编辑器；
  底部媒体工具条。
- 桌面端：弹 Dialog，内部提供与移动端同构的沉浸感。

## 变更内容

1. **默认收起**：线程页不再渲染常驻 `PostComposer`；改为底部一条「发布你的回复」收起的
   入口（`data-testid=reply-open`），点击才展开。
2. **意图展开**：收起的入口、帖子卡片上的「回复」动作（`#/p/<id>?reply=1`）都直接打开
   沉浸式编辑器；关闭后回到只读线程，不残留输入区。
3. **沉浸式编辑器**（新 `ReplyComposer`）：
   - 官方 `Dialog` 承载（移动端全屏、桌面居中），标题栏左 X / 右 `回复`（提交态与禁用态）；
   - 原帖上下文（作者行 + 正文，超高截断）+ `回复给 @author`；
   - 复用 `PostComposer`（markdown、@/#、附件上传），新增 `showTabs` / `hideSubmit` /
     `submitRef` / `onStateChange` 四个纯增量开关，发帖箱行为不变；
   - 打开时压合成历史条目：返回/手势关闭编辑器而不离开线程（复用 `lib/back-close.ts`）。
4. **提交后**关闭编辑器并刷新线程回复列表；草稿按 `reply:<parentId>` 保留。

## 非目标

- 不新增拍照/表情/GIF/投票等媒体能力（工具栏只列真实可用的附件能力，不摆假按钮）。
- 不修改发帖 API、线程数据模型与静态归档语义。
