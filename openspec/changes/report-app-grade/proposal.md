# Proposal: report-app-grade

## 背景（Owner 2026-11-06 三点）

1. **端点会累积**：一天可能开五六个 report 实例（每个 manager 会话一个），当前 `serve --daemon`
   常驻不回收，本地服务与端口会越积越多。
2. **静态导出不该是"另一套界面"**：归档必须**用同一套前端代码**跑——客户端内置一套只读的
   后端接口模拟，POST/PUT/DELETE 一律禁用，于是同一份代码同时服务"后端模式（ep）"与
   "静态模式（无 ep）"。
3. **界面还没到应用级**：导航（返回手势会把页面关掉）、图片预览（移动端不能缩放）等细节
   达不到"Web Application"标准；基准是**微博 App**。

## 变更

1. **租约与自动释放**：服务端持有一个空闲租约，任何 CLI/HTTP 活动续租；`--idle-timeout`
   （默认 30 分钟）到期自动优雅退出并清理 `server.json`；`status --all` / `gc` 用于发现与回收
   残留；manager 的订阅进程在被 kill 后不再留下"半死"服务。
2. **静态模式（mock service）**：导出产物＝**同一个前端构建** ＋ 内联数据快照；前端启动时
   若判定为静态模式，则安装一个只读 API mock（GET 走快照，写操作返回 403 并提示"归档只读"），
   同时隐藏所有写入口并显示归档横幅。`file://` 与任意静态宿主都可用。
3. **应用级 UI**：补齐导航栈与返回语义、图片查看器（双指缩放/双击/下滑关闭/左右切换）、
   列表密度与操作栏、下拉刷新、加载与空态、移动端触控尺寸；以微博 App 为审视基准逐项过。

## 非目标

- 不做账号体系/权限变更（沿用现有后端认证）。
- 不做离线写入队列（静态模式明确只读）。
- 不追求像素级复刻微博视觉，只对齐**交互与信息密度**的应用级标准。
